## Problem

AI 協作需要狀態延續。一次決策的脈絡、一段推理的中間結論、一個設計選擇的理由——這些都需要跨越多次互動持續存在，才能讓後續的工作建立在先前的基礎上，而不是每次從零開始。

但 LLM 本質上是無狀態的。每一次推理都是獨立的函數呼叫：輸入 context window 的內容，輸出回應，然後遺忘一切。模型不記得上一次對話，不記得它為什麼做了某個選擇，甚至不記得它做過選擇。

這個鴻溝由文字 artifacts 來填補。Skill 定義、規格文件、commit message、rules 檔案——這些文字產物承擔了「狀態介質」的角色，把人的判斷力搬運過無狀態的邊界，交給下一次推理使用。整個 AI 協作的基礎設施，建立在一個隱含假設上：只要 artifacts 寫得夠精確，判斷力就能忠實地傳遞。

這個假設是錯的。

---

## Investigation

### 觀察：精細化的反效果

Skill 定義經過多次迭代精煉後，表現開始下降而不是上升。這不是偶發現象——一個 skill 從簡潔的初版到詳盡的成熟版，效果曲線呈現先升後降的拋物線。初期增加規則確實能修正錯誤行為，但超過某個臨界點後，每多一條規則帶來的改善不足以抵消它引入的副作用。

問題出在哪裡？不在規則本身的邏輯，而在文字作為介質的兩層損耗。

### 第一層損耗：編碼（人 → 文字）

當人把判斷力轉換為規則時，必須把隱性知識顯性化。但判斷力運作在無限的情境上——它考慮的是「此刻所有可見與不可見的因素」，而規則只能捕捉有限的條件。每一條規則都是判斷力的有損壓縮。

更微妙的是，人在編碼時會不自覺地省略自己認為「不言而喻」的部分。這些省略對人來說是合理的——同事讀到同一條規則也會自動補上同樣的隱含前提。但 Agent 不會。Agent 照字面執行，沒有被寫下的部分就不存在。

### 第二層損耗：解碼（文字 → Agent）

文字進入 transformer 後，不是被「讀取」的——它被 tokenization 切分，經過多層 attention 加權，最終影響生成的機率分佈。這個過程有一個固有的正規化傾向：

**短文本被展開。** 當輸入簡潔時，模型傾向用自己的分佈來填補空白。一條簡短的規則會被模型的先驗知識「膨脹」，填入作者可能未意圖的假設。規則越短，模型的解釋空間越大，偏離作者意圖的機率越高。

**長文本被選擇性關注。** 當輸入冗長時，attention 機制不可能均勻分配——它必然對某些部分給予更高權重。哪些部分被強調、哪些被弱化，取決於模型的訓練分佈，不取決於作者的意圖。規則越長，被模型「重新排序優先序」的可能性越大。

這兩層損耗不是獨立的，它們複合：規則已經是判斷力的有損版本，transformer 的處理再次變形這個有損版本。最終 Agent 執行的，是一個雙重失真的訊號。

### 棘輪陷阱

兩層損耗的複合產生了一個正回饋迴圈：skill 表現不佳 → 作者增加規則來修正 → 更多文字 → 更多選擇性關注 → 某些規則被弱化 → 新的表現偏差 → 再增加規則。複雜度只增不減，每一輪修正都把 skill 推離最佳長度，但沒有機制把它拉回來。

這就是為什麼 skill 精細化到某個程度後效果會反轉：不是規則邏輯錯了，是介質的承載能力已經飽和。

## Finding

文字介質在人機協作中的失真是結構性的，不是工藝性的。它不能被「寫得更好」所消除，因為損耗發生在兩個獨立的環節——編碼和解碼——每個環節都有不可壓縮的資訊損失。

文字 artifacts 有一個承載上限：存在一個最佳複雜度區間，低於它則規則不足以約束行為，高於它則介質失真吞噬規則的效益。這個區間不是固定的——它取決於 context window 中的其他內容、任務的性質、以及模型的特定版本——因此無法事先計算。你只能在效果下降時回溯判斷自己已經越過了它。

根本問題在於：文字 artifacts 被要求承載「狀態」穿越一個不保狀態的邊界，但邊界的轉換過程（tokenization → attention → generation）本身就不是狀態保持的。介質在傳遞過程中必然變形，變形的幅度隨複雜度增長。

## Application

這個發現劃定了外化策略的天花板。把人的判斷力寫成規則讓 Agent 執行，是目前 AI 協作的主流做法——從 prompt engineering 到 skill 定義到 governance rules，本質上都是同一件事：用文字介質搬運判斷力。介質的結構性失真意味著這條路有不可突破的上限。

這不意味著「不要寫 skills 或 rules」——它意味著每一份文字 artifact 都有一個「失真預算」，而這個預算比直覺預期的小。超過預算的部分不是被忽略，而是被變形，效果比不寫更差。

這引出兩個延伸問題。第一，當團隊把這個有損介質當作協作的基礎——用它來統一品質、傳遞規範、管理產出——會發生什麼？管理策略如果建立在一個會變形的載體上，策略本身是否也受介質限制？第二，如果文字介質有不可消除的天花板，是否存在不依賴外化的替代路徑——把判斷力留在人的內部，而不是試圖搬運它穿越無狀態邊界？

失真預算的實務意涵是：每一份 artifact 在開始撰寫前，就應該問「這份文件的複雜度是否已經接近介質的承載上限」。如果答案是肯定的，增加內容不會讓它更有效，只會讓它更不可預測。此時正確的行為不是繼續精煉文字，而是退一步重新評估：這個判斷力是否真的需要被外化，還是它應該留在操作者的腦中。

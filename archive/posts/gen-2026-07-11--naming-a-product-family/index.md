## 前言

替一族產品命名，常被當成最後才順手處理的表面工作。但一套名字會默默決定三件事：讀者
對每個產品的第一印象、產品之間看起來像不像「同一個框架的子模組」、以及維護者自己會
不會被名字帶著往錯誤的方向想。

本文探討為產品家族命名的方法論。它的骨幹是一個容易被忽略的區分——**品牌與 API
語彙是兩個不同的層**；在此之上，再加三道檢查：名實貼合的標準、錯誤聯想與讀音成本、
以及用多語源避免「同一世界觀」的錯覺。

## 分析

### 一、兩層分離：品牌 vs domain-language

第一個、也是最省成本的洞見：**品牌名和 API/領域語彙是分離的兩層。**

- **品牌**：產品對外的標籤(可以富含隱喻、來自各種語源)。
- **API / domain-language**：程式碼裡的型別、方法、詞彙——應**清晰、精確、通常用單一
  語言(如英文)**，並由該產品自己的治理去強制其一致性。

兩層分離帶來一個實際好處：**換品牌不動一行 API。** 如果一個產品的裁決型別是
`Verdict { Grant, Deny, Abstain }`，那麼不論它的品牌最後叫什麼，這個 API 都不變。這意味
命名的糾結**只發生在行銷層，零 API 成本**——所以命名可以大膽、可以反覆改，不必怕動到
程式。

反過來，這也告訴你**不要**把品牌的隱喻硬灌進 API：即使品牌用了某個領域的意象，API 仍
該用它自己清楚的領域詞，否則程式碼會變成隱喻的俘虜。

### 二、名實貼合的標準：名字即本質

品牌可以有隱喻，但最好的品牌是**名字直接就是核心本質**——讀者一看到名字，不需解釋就
抓到這個產品在做什麼。可以分成三個貼合度層級：

- **名即本質(最佳)**：名字的字面意義就是核心語義(例如一個做「配額」的產品就叫某個
  語言裡「配額/份額」的詞)。零解釋成本。
- **透明隱喻(達標)**：名字是隱喻，但透明到不需背景知識就懂(例如一個「開/閉以調節
  流量」的東西，借一個「會開合的孔」的意象)。
- **需冷知識或字面相反(不及格)**：名字要靠讀者懂某個典故才 get，甚至字面意義指向
  相反方向。這種名字違反「名即本質」，是最該被替換的。

實務判準：**如果你得替一個品牌寫一段典故才能解釋它為什麼貼合，它多半屬於第三層，該
換。** 家族裡若有一個名字明顯低於其他名字的貼合度，它就是最先要重做的。

### 三、錯誤聯想與讀音成本

除了貼合度，兩個「外部性」檢查常被跳過：

- **錯誤聯想**：一個在某語言裡完美貼合的詞，轉寫或跨文化後可能撞上一個沉重或負面的
  意涵。務必查一個名字在目標讀者的語言/文化裡**第一反應是什麼**——尤其當它與另一個
  更常見(且意涵不同)的詞**形近或音近**時。若聯想無法避免，至少要用一個能消歧的
  拼法，並在官方文件附一句 gloss(原意 + 讀音)。
- **讀音與拼寫成本**：對開發者面向的產品，「讀」多於「說」，所以高讀音成本的名字並非
  絕對禁忌——但要**誠實計價**。若一個名字的正字法對目標讀者不透明(唸不出、拼不對)，
  你就是在口耳傳播、會議談話上加了一道摩擦。可接受，但要為它固定一個官方讀音提示，
  並知道自己付了什麼。

一個健康的取捨傾向：**若你一貫地把「名實貼合」放在「讀音成本」之上**，那是一種風格
選擇——只要你為難唸的名字補上 gloss 與讀音，就能把摩擦壓到可接受。反之，若可唸性對你
的傳播比貼合更重要，就在同義詞裡挑一個更好唸的。關鍵是**這個取捨要被意識到，而不是
默默發生**。

### 四、多語源：避免「同一世界觀」的錯覺

替一族產品命名時，若所有名字都來自同一個語源或同一個意象系統(例如全用同一套神話)，
會製造一個錯覺：**它們看起來像同一個框架的子模組**，而不是各自獨立的產品。

刻意讓名字**來自不同語源**，能打破這個錯覺，讓每個產品保有獨立的辨識度。但要注意兩點：

- 不必每個名字都不同語源到極端；重點是**沒有單一語源支配**，而不是強求十二個語言。
- 有一種名字要特別警惕：**全家族裡唯一用「大家的母語/通用語」的那個**。它會像一個
  異物，同時它往往也是語義最窄、最容易撞上既有含義的那個(因為通用語的詞你我都已經有
  既定聯想)。這種「唯一的通用語名字」通常是該重挑的。

多語源不是為了異國情調，而是為了**讓「獨立產品」這件事在名字層就被看見**——名字本身
就在說「我們不是同一個東西的分身」。

## 反思

**命名便宜，所以更該講究。** 因為兩層分離讓「換品牌零 API 成本」，人很容易覺得「名字
之後再說」。但正因為改名便宜，反而沒有藉口將就一個貼合度差、或有錯誤聯想的名字——
成本低意味著你可以、也應該挑到對為止。

**名實貼合與品牌不透明可以並存。** 不是每個名字都必須語義透明：家族的語義其實由
domain-language 承載(第一節)，所以品牌**可以**是一個乾淨、獨特、好念的不透明標籤。
陷阱是為了「品牌也要透明」而硬換一個**更差或有雷**的詞。判準：若一個不透明品牌乾淨、
獨特、無不良聯想，就別為了語義透明而動它；要動的是那些**低於家族貼合度水準、或帶錯誤
聯想**的名字。

**貼合的極限案例是字面相反。** 最該警惕的不及格名字，是那種「靠一個著名典故才聯想到
正確意義、但字面其實指向相反」的名字。它同時踩了「需冷知識」與「字面相反」兩雷。若你
對某個名字有品牌情感(它是既有資產)，這是一個真實取捨：權益 vs 貼合。把取捨攤開，別
讓情感默默決定。

## 結論

可攜的原則：

1. **兩層分離**：品牌(多語源標籤)與 API/domain-language(清晰、單一語言、受治理)是
   兩層；換品牌不動 API，所以命名可大膽、可反覆。
2. **名即本質**：最佳品牌的字面就是核心語義；透明隱喻達標；需典故或字面相反的不及格，
   優先替換。
3. **外部性檢查**：查目標文化的第一聯想(尤其形近/音近的沉重詞)，為難唸的名字附
   gloss+讀音；把「貼合 vs 可唸」的取捨攤開，別讓它默默發生。
4. **多語源避免子模組錯覺**：不讓單一語源支配；特別警惕「全家族唯一的通用語名字」——
   它常是最窄、最易撞義的異物。
5. **改名便宜 ≠ 可將就**：成本低正是挑到對為止的理由；乾淨的不透明名可留，低貼合或
   帶錯聯想的要換；品牌情感造成的權益 vs 貼合取捨，要攤開決定。

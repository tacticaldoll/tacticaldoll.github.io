## 導言

把產物當成共享庫的可逆投影，靠的是一個間接層加一個冪等的重新推導：產物裡每處標註記下一把穩定鍵，重推導時先把舊標註全部剝除、再依庫的當前狀態重貼一次。這個論證已經成立，本文不重述。

但它把幾乎所有的注意力都放在「重貼」那一半——寫出鍵、讀回鍵、依鍵重算。冪等重推導其實有兩個動作：先全清、再重建。重建被仔細論證了；全清則被當成不費力的前置，一句「先把舊標註完整剝除」帶過。本文主張：**全清才是脆弱的那一半。** 若它不對準重建所用的同一把鍵，可逆性會在最不該失效的地方默默崩掉——而且不會有任何錯誤訊息。

---

## 分析

### 隱形的那半：為何剝除的判定依據沒人檢視

重貼是可見的：它把鍵寫進產物，是有輸出、可審計的動作。剝除被歸類為「清理」——一個沒有輸出、只讓東西消失的動作。沒有輸出，就沒人去追問它「憑什麼判定這一段該拆」。

於是一個常見的不對稱出現了：重貼老老實實用鍵，剝除卻偷偷換成兩個看起來等價、其實會漂移的代理——「當前有效項清單」，或「長得像標註的視覺結構」。兩半用了不同的判準，而沒人盯的那半正是 bug 的住處。

### 兩種失效，一個根因

依「當前有效項清單」剝除：清單只認得此刻還在庫裡的項目。一個被移除的項目，顯示值已不在清單，於是它留在產物裡的舊標註不被認出、清不掉，成為孤兒。最諷刺的是，可逆投影最自豪的宣稱正是「移除一個項目，重推導一次，全產物同步」——而「移除」恰恰是清單驅動剝除唯一漏掉的操作。最該可逆的事，成了唯一不可逆的事。

依「視覺結構」剝除：規則去比對「看起來像機器標註的形狀」。但作者親手寫的內容可能恰好同形——同樣的引用框、同樣的粗體開頭。剝除於是連人寫的東西一起刪掉。維護的動作反過來破壞了被維護的產物，這與可逆投影談往返無損時的母題完全同形：本要維護產物的操作，摧毀了維護的基礎。

兩種失效方向相反——一個清得不夠、一個清得太多——但根因是同一個：剝除沒有對準重貼所用的那把鍵。

### 統一原理：鍵是身分，不只是連接欄位

可逆投影把穩定鍵定位成「重貼時的連接欄位」。本文把它的角色擴張一格：鍵同時是「這一段到底是不是機器產物」的身分證。

剝除真正要回答的問題是「這段該不該拆」，而唯一正確的判準是「它是不是我（這台機器）當初蓋過章的」。成員資格（在不在當前清單）與外觀（像不像機器標註）都只是這個身分的代理，而代理會漂移：清單隨策展增刪，外觀和人類書寫撞型。鍵不漂移，因為它是機器自己當初蓋下的章。所以剝除必須**主張身分**（移除帶有該鍵的一切），而不是**推測身分**（猜哪些看起來該移除）。

### 冪等不等於正確

clean-then-rebuild 之所以宣稱可以反覆重跑而結果穩定，隱含一個前置條件：全清真的把產物帶回了零標註的基準態。剝除不完整時，這個前置從未成立——系統停在一個「穩定但帶髒汙」的不動點。

對這份帶孤兒的產物再跑一次，看起來仍是無變更：孤兒沒被重新加上，但它也沒被移除，只是賴著不走。這個 no-op 是僥倖，不是正確。它揭穿一個容易誤信的等式：冪等性的「重跑無變更」只證明了系統到達某個不動點，並沒有證明那個不動點是乾淨的。一份產物可以同時是冪等的、也是錯的。可逆投影把冪等當成可信的基石，而這塊基石的成色，完全取決於剝除是否真能歸零。

## 反思

可逆投影主張把工程精力從「鑄造瞬間的完美」移到「沉澱後的策展，加一條獲授權的冪等傳播」。本文補上一個但書：那條傳播步驟的可信度，等於它**剝除那半邊**的可信度。一個只驗證重貼、不驗證剝除的稽核是半稽核——它讓你以為移除會扇出到所有產物，實際不會；而且這種錯是靜默的，孤兒不會報錯，它只是留著。要讓「源頭修一次、全域回滾」名實相符，剝除與重貼必須對準同一把鍵，而且兩半都需要對抗性的驗證：至少要有一個會製造孤兒的反例、一個會製造誤刪的反例，分別逼出兩個失效方向。

兩條投影戒律還是串聯的，不是並列。可逆投影談的「往返無損」是說鍵必須在讀入—寫出的往返中存活；本文談的「剝除對準鍵」則以鍵的存活為前提。鍵若沒活下來，重貼找不到連接欄位，剝除也失去身分依據——兩半會一起垮。所以往返無損是「對準標記剝除」的前置條件，先有鍵能存活，才談得上靠鍵來拆。

邊界要誠實：對準標記的剝除，前提是標記被可靠地蓋上、且格式穩定。若有歷史產物在標記制度建立之前就生成，帶著無標記的舊式標註，那麼「主張身分」會把它們判為非機器產物而保留下來。這通常是比誤刪更安全的預設——寧可留下也不要錯刪人寫的內容——但代價是清理這些遺留物需要另闢一條一次性的遷移路徑，而不是回頭放寬身分判定。一旦放寬，就又掉回「靠外觀猜」的老陷阱。

## 實務對照

決定剝除是否安全的，是它用什麼判準認出「該拆的東西」：

**錯誤做法一**——剝除依「當前有效項清單」，只有重貼那半對準了鍵：

```
重貼規則 = 依當前項寫入「鍵 + 顯示值」      （這半對準了鍵）
剝除規則 = 列舉「當前有效項」去找舊標註      （這半換成了代理）
   └─ 被移除項的舊標註 → 已不在清單 → 認不出 → 孤兒殘留
```

**錯誤做法二**——剝除依「視覺結構」：

```
剝除規則 = 比對「長得像機器標註的形狀」
   └─ 作者同形內容 → 被誤判為機器產物 → 連帶刪除
```

**正確做法**——兩半對準同一把鍵：

```
重貼規則 = 寫入穩定鍵
剝除規則 = 移除「帶有該鍵的一切」            （與重貼主張同一身分）
   └─ 被移除項 → 標記仍在 → 認得出 → 清除
   └─ 作者內容 → 無此標記 → 判為非機器產物 → 保留
```

差別在於：前兩者讓剝除去猜身分，後者讓剝除去主張身分。猜會漂移，主張不會。

## 結論

**重建被仔細論證，全清被當理所當然——但全清才是脆弱的半邊。** 冪等重推導的兩個動作裡，沒輸出的那個才藏著錯。

**剝除依清單或外觀判定，會在「移除」這個最該可逆的操作上出錯。** 依清單會漏掉被移除項的孤兒，依外觀會誤刪同形的人寫內容；兩個方向相反，根因都是沒對準鍵。

**鍵是身分證，不只是連接欄位。** 剝除要主張身分（拆掉帶該鍵的一切），而非推測身分（猜哪些看起來該拆）。成員資格與外觀都是會漂移的代理。

**冪等不等於正確。** 帶孤兒的不動點同樣穩定，重跑同樣無變更。冪等只證明到達了某個不動點，沒證明它乾淨。

**兩條投影戒律串聯成立。** 往返無損讓鍵得以存活，是前置；剝除對準鍵是建立其上的對稱要求。可逆性要真的成立，剝除與重貼必須是同一把鍵下的互逆操作，且兩半都要被對抗性地驗證。

## 背景

一個 AI agent 每次啟動都從零開始。它的工作記憶只包含當下 context window 中的內容——自動載入的設定檔，加上這次對話中人類提供的訊息。這個架構事實有一個不直觀的後果：agent 推理的品質，被載入知識的品質所限定。

但問題不只是資訊是否完整。更深層的問題在於知識的結構。當人類指導 agent 時，自然傾向傳遞結論而非產生結論的推理過程。這是合理的——效率高，而且人類往往無法清楚說明為什麼某個結論是對的，只知道它是對的。結果是一個系統性的模式：agent 持續接收到終點而非路徑，必須從上下文線索重建推理。

本文探討這個現象為何發生、斷裂後什麼會出問題，以及對於我們如何組織 agent 工作所依賴的知識，這意味著什麼。

---

## 分析

### 無狀態的 Agent

人類協作者會在數週的工作中累積脈絡；agent 的記憶在每次對話之間完全重置。留存下來的，只有被刻意外化的東西——寫進在 session 開始時自動載入的檔案。

這造成了根本性的不對稱：人類攜帶著關於專案歷史、過去決策背後的推理、失敗嘗試的教訓的豐富模型。Agent 只攜帶被寫下的東西。當人類給出指令時，他們從完整模型推理；當 agent 回應時，它從已載入的 context 加上推斷推理。

人類模型與 agent 已載入 context 之間的落差，由推斷填補。推斷並不不可靠——它可以產生好的結果——但它不等同於知識。推斷可能在有規律的方式上系統性地出錯，尤其當缺失的 context 遵循一個不直觀的規則時。

### 認知負擔作為傳遞瓶頸

認知負擔描述的是持有和處理資訊所需的心力。當人類向 agent 傳遞指令時，他們自然地最小化自己的認知投入——他們描述想要什麼，而不是如何得出想要這件事的過程。

考慮以下兩種表述的差異：

- 「實作新模組之前不要跳過考古步驟」
- 「實作新模組之前不要跳過考古步驟——考古會從 legacy 程式碼中提取行為承諾，若跳過，這些承諾將在重寫中被靜默丟棄」

第一種更短、傳遞成本更低。但只接收到第一種指令的 agent，可以在形式上遵守卻違反精神——它知道規則，但不知道打破規則的代價。當面臨加快進度的壓力時，沒有「為什麼」的 agent 沒有依據去抵抗捷徑。

認知負擔也解釋了為何知識在交接過程中衰減。當開發者矯正 agent（「不，用這種方式」），他們在傳遞一個從未被清楚說明的經驗所形成的結論。矯正被傳遞；推理沒有被傳遞。

### 善意矯正的系統性風險

矯正是人機協作中主要的回饋機制，幾乎總是善意的。但它系統性地斷裂因果鏈。

當人類說「這次先跳過考古，我們趕時間」，agent 學到了一個行為模式，卻沒有學到它的邊界條件。未來的 session 可能在應該窄泛應用的地方廣泛應用這個模式。下達矯正的人攜帶著完整的 context 說明為什麼在那個實例中跳過是安全的——目標元件沒有 legacy 對應物、行為是全新的，諸如此類。這些 context 都沒有被傳遞。

風險隨時間累積。每一個未被記錄的矯正，都在 agent 的行為與最初意圖之間加深了一道裂縫。這道裂縫是不可見的——沒有人記錄它——直到某個邊界案例暴露它為止。

以文件中的誤解為例：某份文件曾寫道一個元件使用 subprocess 進行權限切換。這是錯的。矯正被執行了。但若只有修正後的文字留存——沒有記錄原始說法為何是錯的、正確模型實際上是什麼——下一個在這個領域工作的人可能重蹈同樣的錯誤，或犯下一個相關的錯誤，而已記錄的矯正並不涵蓋它。

記錄因果鏈（「該元件直接在行程內完成權限切換——沒有子行程，沒有 fork，沒有中間行程」）比單獨記錄矯正後的結論更耐久。

### 因果斷裂

**因果斷裂**（Causal Breakpoint） <!-- term:CausalBreakpoint -->發生在 agent 的知識庫包含結論但沒有產生它的推理鏈時。Agent 可以在預期案例中正確應用結論，但無法對邊界案例、例外情況，或需要理解原始意圖的情境正確推理。

> [!IMPORTANT]
> **因果斷裂** <!-- term:CausalBreakpoint --> (Causal Breakpoint): AI Agent 運算中由於上下文視窗或靜態程式碼中關鍵因果資訊缺失，導致無法正確推演系統狀態的現象 <!-- anchor:CausalBreakpoint -->


領域驅動模式 文件通常被當作知識儲存庫——準確性是首要標準。但對 agent 而言，更相關的標準是：這份文件是否保留了足夠的因果 context，讓 agent 能對文件作者未曾預料的情境正確推理？一份準確的文件仍然可能斷裂因果鏈，如果它只傳遞結論而不傳遞來源的話。

## 結論

Agent 的無狀態性，使因果鏈的外化成為結構性的必要，而非可有可無。這與傳統上對文件的思考方式有本質的不同。傳統文件通常為人類參考而寫——摘要、操作指南、架構概覽。它們服務的是人類記憶，而人類記憶在 session 之間有連續性，可以從經驗填補空缺。

為 agent 撰寫的 governance 文件必須做一件不同的事：它必須提供人類會從記憶中補充的推理基礎。這意味著它需要包含的不只是什麼是真的，還有為什麼是真的，以及搞錯了的代價是什麼。

這重新框架了什麼讓 governance 文件有價值的問題。標準不是「這是否準確？」而是「這是否保留了足夠的因果 context，讓 agent 能對邊界案例正確推理？」

對矯正實踐的啟示很重要。當人類覆寫 agent 的行為，應該記錄的不只是覆寫本身，還有推理。這在認知上是昂貴的——它要求人類說清楚他們可能從未明確化的推理——但這是防止覆寫產生新因果斷裂 <!-- term:CausalBreakpoint -->的唯一方式。

## 結論

**Agent 推理品質受 context 品質限定** — 已載入 context 中的空缺由推斷填補。推斷可能系統性地出錯。替代方案不是更多推斷，而是更好的 context。

**矯正傳遞結論，不傳遞推理** — 每一個未記錄的矯正都是潛在的因果斷裂 <!-- term:CausalBreakpoint -->。斷裂是不可見的，直到邊界案例暴露它。

**領域驅動模式 文件是因果鏈保存系統** — 其價值不只是準確性，而是它們能在多大程度上讓人對文件作者未預料的情境進行正確推理。

**認知負擔是知識傳遞的對手** — 最小化傳遞投入的自然傾向會剝離因果 context。反制方式是讓剝離的代價可見：在每條規則旁邊記錄該規則的利害關係。

**「為什麼」比「什麼」更耐久** — 結論可能被誤用。帶著來源的結論可以被正確應用到新情境。只記錄結論的 governance 文件，建造的是脆弱的知識基礎。

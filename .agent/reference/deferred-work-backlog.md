# 延後工作 Backlog

`crystallize-report.schema.yaml` 的擴張上限規約兩處要求：無法回溯至系列問題域的新增論證「移入後續 backlog」。本檔就是那個目的地。

它不是權威來源，也沒有任何腳本讀它。它的唯一用途是讓被判定為「本次不做」的項目有一個**單一、可被搜尋、跨 session 匯總**的落點——因為延後項目若只寫在各自的 `series-map.md` 裡，就沒有人會在下一個 session 開始前看到它們。

> [!NOTE]
> 與 [post-series-recrystallization-backlog.md](post-series-recrystallization-backlog.md) 的關係：那份是**已消耗**的再結晶入口（10 個母系列、75 篇候選貼文全部封存），保留為 provenance 紀錄，不再是活躍佇列。本檔是活躍佇列。

## 1. 術語治理

### 1.1 詞庫的字界與跨域撞名（已記入永久防線，機制未解）

詞庫以中文詞為主鍵、單一命名空間，而錨點注入對中文不設字界。這造成兩種形式的誤命中：

- **跨域撞名**：同一個中文字串在不同領域是不同概念。`Distill`、`Knowledge`、`Projection`、`Compose`、`DataShape` 承載專案治理域的定義，而其主鍵是機器學習散文的常用字串；`Subject`／`Object` 承載 Linux 權限域的定義，而其主鍵是責任歸屬語境的常用字串。
- **子字串命中**：通用二字詞會匹配到更長詞的內部。`量化` 落在「輕量化」、`技術債` 落在「技術債務」、`導讀` 落在「誤導讀者」。

**已處理**：`Subject`／`Object` 與其餘七鍵已降至 level 3，已發布語料已經 reanchor 補齊；操作規則已寫入 [agent-operating-guideline.md](agent-operating-guideline.md) §6（降級判定必須檢視命中位置，不得只檢視定義）；[injector.py](../scripts/domain/terminology/injector.py) 的錯誤註解已修正。

**未處理**：作用域機制本身。英文別名以 `\b` 防住同一類破壞，中文沒有對應手段——中文無正字法字界，正確的防護需要分詞或最長匹配排除表，兩者皆不存在。

已知的可行方向與各自的代價：

| 方向 | 代價 |
| :--- | :--- |
| 為術語加上 `domain` 欄位，錨定時只在符合領域的貼文生效 | 需要可靠的領域判定；`classify_domain` 目前每篇只取首個命中 |
| 最長匹配排除表（例如 `量化` 不在「輕量化」內生效） | 需人工維護，且漏列即失效 |
| 引入中文分詞 | 新增外部相依，且分詞本身會錯 |
| 維持書寫規避 | 零成本，但每個 session 都要重跑一次命中位置檢視 |

此問題在 2026-09-08-b、2026-09-08-c、2026-09-09-a 三個 session 各自被記錄並各自以書寫規避處理過一次——重複三次本身就是機制缺席的證據。

### 1.1a 同一機制也影響領域分類（新增，已造成已發布缺陷）

字界缺口不只影響術語錨定，也影響 `taxonomy.json` 的領域分類。發布 2026-09-08-a 時，`gen-recrystal-2026-09-08-a-01--proxy-gap-mechanisms` 被分類為 `AI 經濟與社會`，而它是一篇機器學習報告。成因是關鍵字 `估值` 命中「評**估值**系統性偏高」——落在「評估」＋「值」的跨詞邊界上；而同一篇的 `機器學習` 關鍵字命中 0 個，所以那個唯一的錯誤命中依「依序取首個命中」的定案勝出。

這比錨定注入嚴重，因為領域分類進入已發布貼文的 `tags` 且是檢索面。同一次發布還有 `-10--falsifiable-experiment-contract` 因 0 命中而沒有領域標籤。

兩者都**未手動修正**：`domain_tag` 依 `init-handoff` 規約嚴禁 AI 手填。可行的修法各有代價：

| 方向 | 代價 |
| :--- | :--- |
| 移除或收窄 `估值` 這類易跨界的關鍵字 | 會降低 AI 經濟類貼文的召回 |
| 為關鍵字加最小長度或字界條件 | 與 §1.1 同一個未解問題 |
| 為機器學習類補足關鍵字覆蓋 | 只治這一篇，不治機制 |
| 允許人工覆寫 `domain_tag` 並留記錄 | 需要修改 `init-handoff` 的嚴禁條款 |

`audit_kb.py` 會以 `[DOMAIN AMBIGUITY] ... SINGLE_HIT` 曝光這類單一命中，但它是 INFO 而不阻斷。

### 1.1b 術語採收未剝除程式區塊

`prepare_handoff.py` 的術語採收把整份報告當散文掃描，包含 ```python``` 區塊與範例字串。發布 2026-09-08-c 時，`gen-recrystal-2026-09-08-c-14--refutability-contract` 得到 `端到端效用` 與 `貢獻利益` 兩個標籤，而這兩個詞在該篇**只出現在 python 契約字面值裡**（`"metrics": [..., "每件貢獻利益"]`），不是該篇的核心討論對象。

這違反 `init-handoff` Task 4 的「標籤首見即引」——該規約要求標籤是該篇的核心討論對象，而程式區塊裡的字串不構成討論。修法是採收前以既有的程式區塊剝除邏輯（`injector.py` 已有一份）先行處理；影響是每個 session 的標籤品質，不影響正文。

此缺陷已發布但未回溯修正：handoff 在管線結束時已退役，而重跑需要重建 handoff，代價高於兩個過路標籤的損害。

### 1.1c reanchor 非冪等，且第二次 apply 會刪除內容（阻斷級）

> [!WARNING]
> **在此修好之前，不要執行 `reanchor.py --apply`。** 它的第二次執行會刪除作者寫的定義區塊。

工作流 §4 要求「術語庫未變時重跑應為 no-op（零貼文變更）」。實測不成立：

1. 2026-09-08-a 發布後，`選擇偏差`／`條件命題的前提破壞`／`中介誤認`／`單射` 被 promote 進詞庫，於是 5 篇已發布貼文各命中 1–2 個新術語，`--scan` 報 `+1`／`+2`（自我修復，符合預期）。
2. `--apply` 之後，`--scan` 改報 `-1`／`-2`——同一組錨點又要被移除。
3. 第二次 `--apply` 實際刪掉了一整個 `> [!IMPORTANT]` 區塊，其中含作者寫的 `條件命題`（Conditional Claim）定義。**這是已發布內容的資料遺失。**

根因是插入端而非移除端：reanchor 把新定義**接在既有定義行的尾端而不換行**，產生 `> **條件命題**（Conditional Claim）：…無條件事實。> **選擇偏差** <!-- term:SelectionBias -->：…` 這種一行兩定義的形狀；移除用的 regex 預期一行一個定義，於是下一輪把整個區塊視為不可解析而整段清掉。

**本次處置**：內容已由 `git checkout` 還原，未提交任何遺失。`--apply` 不再執行。5 篇的自我修復錨點因此**尚未補上**——那是可接受的欠帳（缺錨點只是少一次雙語標註），而執行它的代價是刪內容。

**另一個相關但已修的缺陷**：注入器會把錨點插進作者既有的粗體區間內部，產生 `**機制二：**條件命題的前提破壞**（Broken Premise）…**` 這種嵌套粗體。`injector.py` 的註解本來就記載這個失效模式，只是假設僅 level 3 會觸發。本次以來源改寫處理（把術語移出作者粗體，如 `**機制二**：條件命題的前提破壞`），報告端與已發布端同步修正，兩篇的奇數粗體行歸零。根因修法是讓注入器跳過落在粗體內部的出現位置，未做。

### 1.1d 兩個已排除的解法，與一個可行設計

§1.1 的表列出四個方向而沒有排序。以下把其中兩個「不需新相依」的想法實測掉，並說明為什麼「最長匹配排除表」的代價其實可以移除。

**已排除：語料統計自動判定。** 兩種設計都以專案語料本身當詞彙來源，都用 `量化`／`技術債`／`導讀` 當陽性對照，都失敗：

| 設計 | 實測結果 |
| :--- | :--- |
| 單字鄰接集中度 | `量化` 的最大黏著形是 `距量化`（距離＋量化，純相鄰），佔比 8%；真正的 `輕量化` 沒進前四 |
| 鄰接多樣性（accessor variety） | `技術債務` 判「存疑」，`的技術債` 反判為「詞」；陰性對照 `結晶` 連續誤報 |

根因是語料規模，不是設計。每個鍵在全部語料只有 20–53 次命中，用一位數的鄰接計數估分佈就是雜訊。兩者量到的都是**相鄰**而非**內嵌**，而區分兩者需要知道「包住鍵的那一段是不是一個詞」——沒有詞表就沒有答案。此路在本專案的語料量下封閉，不必再走一次。

**可行設計：guard patterns，由詞表生成。** §1.1 把排除表的代價寫成「需人工維護，且漏列即失效」。人工維護那一半可以去掉——排除表能從一份靜態中文詞表生成，不必手寫。

而注入端已經做好一半：[injector.py](../scripts/domain/terminology/injector.py) 的 `patterns.sort(key=len, reverse=True)` 已是最長匹配優先，殘留失效只發生在「包住它的詞不在 alternation 裡」。所以：

1. 詞表以靜態資料檔進 `lexicon-core/databases/`（是資料，不是執行期相依）
2. 編譯 lexicon 時，對每個 level<3 的 `zh` 鍵 K，取詞表中所有真包含 K 的詞 W 作為 guard 併入同一個 alternation
3. `replacer` 遇到 guard 就原樣回傳

`輕量化` 一旦在 alternation 裡且比 `量化` 長，`量化` 就不可能命中它內部。不需要新的匹配機制，只是多幾個候選加一個 no-op 分支。同一組 guard 也能餵給 `taxonomy.py` 的關鍵字比對，那是 §1.1a 裡 `估值` 命中「評**估值**系統」的同一個洞。

**風險面比想像小**：427 個參與錨定的 zh 鍵中，2 字鍵 18 個、3 字鍵 40 個。高風險集中在這 58 個，guard 不必覆蓋全部。

**未決的代價**：詞表的授權與體積，及其與 §10.1「資料庫目錄保持極簡」的張力；guard 可能誤殺（某術語真的該在更長的詞裡錨定時）；詞表未收錄的包含詞仍會漏，是嚴格改善而非完全解；alternation 目前約 9,200 字元，膨脹幅度需實測。

### 1.2 未收錄的主題 tags

以下詞在既有語料有實質內容支撐，但尚未進入詞庫：`模型評估`、`驗證設計`、`選擇偏差`、`部分識別`、`自然實驗`、`預註冊`、`可重現性`。

收錄前需先確認它們的主鍵不會落入 §1.1 的兩種誤命中。§1.1d 已證明這道確認無法機械化，只能逐鍵檢視語料中的實際命中位置。

**治理語彙的候選與一次已完成的裁決。** `變更溯源`、`一次性內化資產`、`去專案化`、`知識漏斗`、`溯源` 五個詞在指引與報告中已有實質用法而未收錄。其中 `溯源` 是唯一的短鍵，已逐一檢視語料中全部 22 次命中：全為 `溯源標記`／`可溯源`／`被溯源`／`沒有溯源` 等真用法，危險形 `追溯源`（`追溯`＋`源頭` 跨詞邊界）零命中，故今日可收錄。此裁決是快照而非保證——未來出現「追溯源頭」即失效。其餘四個為 4 字以上，落入誤命中的機率低。

## 3. 再結晶：展開方向

以下項目由各 session 判定為「本次不展開」，理由是無法回溯至該系列的問題域。它們各自是獨立主題，需要各自開題而非併入既有系列。

**判準與識別**

1. **交互作用的正面方法** — 已證明逐軸替換無法處理交互、殘差無法區分交互與未列座標，但沒有交互設計的正面方法。二乘二與更高階設計在成本受限下如何取捨。
2. **高維語義結構的劃分權責** — 模式與群的劃分依賴表示與距離的選擇，而該選擇通常無人負責。誰有資格下這個劃分、依據什麼、如何記錄——這是治理問題而非技術問題。
3. **不可得欄位的宣稱強度分級** — 已提出把不可得的契約欄位明文標記而非留空，但沒有給出標記之後宣稱強度該如何降級的規則。
4. **多指標評估與名次的張力** — 增加指標能暴露取捨，代價是結果無法排序，而市場需要名次。如何在不可排序的評估結果上做採購決策。
5. **單消費者元件的邊界驗證** — 歸屬判準的輸入是兩個以上消費者，而永遠只有一個消費者的元件無法驗證自己的邊界。該採取什麼替代判準。
6. **忠實度不可量測時的解釋策略** — 動作集合無上界的判定依賴「誰決定了那個動作」，而在以回呼或工具授權為介面的系統上，授權來源的追溯本身是獨立問題。

**邊界與強制**

7. **代理系統的放行範圍不可列舉** — 授權閘門的第二個旋鈕需要可列舉的動作集合。模型被賦予工具能力後，可執行動作是組合出來的，此時放行範圍必須改以能力邊界描述，而能力邊界的完備性無法從內部證明。
8. **覆核者資訊來源的獨立性** — 人工節點的第五個必要條件是覆核者的判準必須與模型可取用的資訊不同，而它通常最貴。誰有資格建立這條獨立管道、成本如何分攤。
9. **動態語言的守界替代方案** — 把藍圖鎖進型別在表達力弱的語言裡做不到，此時能守的只有回饋延遲較長的層。在動態語言上取得秒級回饋的可行手法。
10. **孤島架構的成本交叉點** — 橋接數量在核心數的平方階成長，因此孤島架構的維護成本增長快於中央架構，兩者存在一個交叉點。那個交叉點的位置與判定方式。
11. **共用序列化格式造成的隱性耦合** — 波及範圍計算只看相依邊，而兩個形式上獨立的核心可以因共用一個資料格式而必須同步發布。格式作為隱性相依邊的量測方式。

**量測與實作**

12. **標籤延遲下的世代分群實作** — 世代必須按產生時的政策版本分群報告，但沒有給出在既有資料倉儲上的實作路徑。
13. **共用資產的資本報酬歸屬** — 同一座資料中心服務多類業務時，AI 的資本報酬率不是可計算的量。在既有分部報告制度下能做到什麼程度的間接觀察。
